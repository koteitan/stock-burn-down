# 備蓄バーンダウンチャート
缶詰・レトルト・水などの備蓄が賞味期限に沿ってどう減っていくかを、種類ごとのグラフで表示するサイトです。

サイト: https://koteitan.github.io/stock-burn-down/

## 使い方
### 備蓄と目標を入れる
1. 「追加」に 種類・内容・数・賞味期限 を入れて [追加] を押します。
   - 数を空にすると 1 になります。
   - 賞味期限は YY/MM/DD（年は西暦の下 2 桁）で入力します。例: 23/12/31 = 2023年12月31日。YYYY/MM/DD や YYMMDD でも入力できます。
   - 種類は空でも追加できます（グラフでは「（種類なし）」になります）。
2. 「目標リスト」の下のフォームに 種類・目標数 を入れて [追加] を押します。目標は 1 種類につき 1 件です。同じ種類を追加すると目標数を上書きします。
3. 備蓄を 1 つ使ったら、備蓄リストの [１つ消費] を押します。
   - 備蓄リストの数が 1 減ります。0 になった行は消えます。
   - 消費履歴に 消費日時・種類・内容・消費数・賞味期限 の行が 1 行増えます。
4. [編集] を押すと、その行が入力欄に変わり、ボタンが [完了] [キャンセル] [削除] になります（備蓄リスト・目標リスト・消費履歴で共通）。
   - [完了] を押すと、入力した内容で上書きします。
   - [キャンセル] を押すと、何も変えずに閉じます。
   - [削除] を押すと、行を削除します。消費履歴の行を消しても、備蓄リストの数は戻りません。
5. 消費履歴の表は種類ごとにまとめて表示します。各まとまりの見出し行の [チャート開始日前の消費履歴を消す] を押すと、確認のあと、その種類のチャート開始日より前の消費履歴を削除します。

### 備蓄リストの並び順
- 最初は 賞味期限 → 種類 → 追加順 の優先順で並びます。
- 「賞味期限」「種類」「追加日」のヘッダを押すと、その列が最優先になります。最優先の列のヘッダをもう一度押すと、昇順と降順が入れ替わります。
- ヘッダの ▲（昇順）/ ▼（降順）の横の数字が優先順位です。
- 並び順はブラウザの localStorage に保存され、次に開いたときに復元されます。
- 賞味期限は YY/MM/DD で表示します（消費履歴も同じ）。

### グラフの見方
グラフ群の上の「チャート範囲 [start] -- [end]」の範囲で、種類ごとに 1 枚ずつ描きます。最近更新した種類ほど先に並びます。
- 左端は start（チャート開始日）です。
- 右端は、end が空欄ならそのグラフの賞味期限の最大値、end があれば end と賞味期限の最大値の小さいほうです（その日を含みます）。範囲の外の線は枠で切ります。

縦軸は在庫数で、どの線も (start, N) から単調に減ります。N は start 時点の在庫数（いまの備蓄 + start 以降に消費した個数）です。

- 青い線（消費実績）: 実際の在庫数です。
  - (start, N) -- (t₁, N-c₁) -- (t₂, N-c₁-c₂) -- ... -- (今, N-C)
  - t_i は消費日時、c_i は消費数、C は start 以降の消費数の合計です。
  - 線の傾きが消費のペースです。この傾きを延ばすと、いつ在庫が目標を下回るかを予測できます。
- 緑の線（賞味期限）: 各品目をちょうど賞味期限の日に消費した場合の在庫数です。賞味期限を 1 つ過ぎるごとに 1 つ減ります。
  - (start, N) -- (e₁, N-1) -- (e₂, N-2) -- ... -- (e_N, 0)
  - e_k は、賞味期限を早い順に並べたときの k 番目です。start より前の賞味期限は start の位置に置きます。
  - 消費してもこの線は動きません。青い線がこの線より上にある日付では、その差の個数が賞味期限切れになっています。
- 橙の破線（目標）: 目標数です。
- 最後に、すべての種類をまとめた「全体」グラフを描きます。在庫・消費・目標数はすべての種類の合計です。
- 緑の線の点の横の小さい文字は内容です。内容が空か、種類と同じときは書きません。青い線の最後の点には、いまの在庫数 N-C を書きます。
- グラフにマウスを乗せると、その日付の消費実績・賞味期限・目標の値と品目を表示します（タップまたは ← → キーでも表示します）。
- 備蓄リストでは、賞味期限切れの品目に「期限切れ」、30 日以内に切れる品目に「まもなく」と表示します。

### メニュー（右上の ≡）
- テーマ: ダーク / ライト / システム
- 言語: 日本語 / 英語
- 保存先:
  - ブラウザ: このブラウザの localStorage に保存します。
  - nostr ネットワーク(暗号化): NIP-07 のブラウザ拡張機能（nos2x, Alby など）で暗号化と署名をして、nostr リレーに保存します。同じ鍵を使えば別の端末からも同じデータを見られます。
- github / ライセンス

保存先が nostr のとき、タイトルの横に状態を表示します。

| 表示 | 意味 |
|---|---|
| nostr 未認証です。ブラウザ拡張機能で nostr に接続してください（「ブラウザ拡張機能」は [NIP-07 の説明](https://welcome.nostr-jp.org/tutorial/nip-07.html) へのリンク） | NIP-07 拡張機能が見つからないか、公開鍵の取得を拒否された |
| nostr 読み込み中 | リレーから取得中（読み込みが終わるまで編集できません） |
| nostr イベントがひとつもありません | 自分の kind:30078 イベントが 1 つもない |
| 備蓄リストがみつかりません | kind:30078 イベントはあるが、このサイトのものがない |
| ユーザー名:[name] で xx イベント受信済み | 読み込み完了。name は kind:0 の display_name（なければ name、届くまでは短縮した npub）、xx は受信したこのサイトのイベント数 |
| 復号できないイベントが n 件あります: (エラー内容) | このサイトのイベントのうち復号できないものがある（NIP-44 を持たない拡張機能で NIP-44 のイベントを読んだときなど）。読めない内容を上書きしないように、編集と保存を止める。NIP-44 を使える端末で一度開くと NIP-04 に書き直されて読めるようになる |
| nostr 保存中 / nostr 保存済み / nostr 保存に失敗しました | 保存の状態（失敗したときは、次に変更したときに再送します） |

## サイト管理方法
### 必要なもの
- Node.js 22 以上、npm

### ビルドとテスト
```sh
npm ci
npm run build      # dist/ に出力
npm test           # 単体テスト (vitest)
npm run typecheck  # 型チェック
npm run dev        # 開発サーバー
```
`dist/` は相対パス（`base: './'`）でビルドするので、どのパスに置いても動きます。

### テスト用の URL パラメータ
- `?today=261201`: 今日を 2026-12-01 として動かします（YYMMDD、YY/MM/DD、YYYY-MM-DD のどれでも可）。時計を日単位でずらすので、追加日・消費日時・グラフの「今日」・期限切れの判定がすべてその日になります。nostr イベントの created_at だけは実際の時刻です。
- `?lang=en` / `?lang=ja`: 表示言語をその言語に固定します。保存されている言語設定は変えません。固定中はメニューの言語を選べません。
- 例: `?today=261201&lang=en`。パラメータが効いているときは、メニューの下に `debug: today=26/12/01 lang=en` と出ます。

### デプロイ
main ブランチに push すると、GitHub Actions（`.github/workflows/deploy.yml`）がビルドして GitHub Pages に公開します。CI はビルドとアップロードだけで、lint やテストは実行しません。GitHub のリポジトリ設定で Settings → Pages → Source を「GitHub Actions」にしておく必要があります。

### 構成
- TypeScript + Vite + React
- [rx-nostr](https://github.com/penpenpng/rx-nostr)（nostr 通信）、[react-i18next](https://github.com/i18next/react-i18next)（日本語 / 英語）
- `src/chart.ts`: グラフの点列（消費実績・賞味期限）と目盛りの計算
- `src/components/`: 画面の部品（グラフ、追加フォーム、備蓄リスト、目標リスト、消費履歴、メニュー）
- `src/useStore.ts`: 設定・リストの状態と保存先の切り替え
- `src/storage.ts`: localStorage の読み書き
- `src/nostr/`: リレー探索、NIP-07、読み込みと保存

### 保存形式
#### localStorage
キー `stock-burn-down` に次の JSON を保存します。

```json
{
  "version": 1,
  "settings": {
    "theme": "dark",
    "lang": "ja",
    "storage": "browser",
    "chartStart": "2026-11-01",
    "chartEnd": "",
    "stockSort": {
      "order": ["expiry", "category", "added"],
      "desc": { "expiry": false, "category": false, "added": false }
    }
  },
  "stocks": [
    {
      "id": "8f0c…",
      "addedDate": "2026-11-08",
      "category": "缶詰",
      "content": "シーチキン",
      "count": 3,
      "expiry": "2027-06-01"
    }
  ],
  "targets": [{ "id": "1b2e…", "addedDate": "2026-11-08", "category": "缶詰", "count": 5 }],
  "history": [
    {
      "id": "c7d1…",
      "at": 1794096000000,
      "category": "缶詰",
      "content": "サバ",
      "count": 1,
      "expiry": "2027-02-15"
    }
  ],
  "updatedAt": { "缶詰": 1794096000000 }
}
```

- `settings.stockSort` は備蓄リストの並び順です（`order` は優先順、`desc` は降順かどうか）。
- `settings.chartStart` / `settings.chartEnd` はチャート範囲の始まりと終わりです（`chartEnd` は空欄可）。保存先が nostr のときも localStorage に保存します（nostr には保存しません）。
- `history` は消費履歴です。`at` は消費日時（Unix ミリ秒）です。
- `updatedAt` は種類ごとの最新更新日時（Unix ミリ秒）で、グラフの並び順に使います。
- 保存先が nostr のときは `settings` だけを保存します。ただし、ブラウザから nostr に切り替えたときは、ブラウザにあったデータを nostr に保存し終えるまで `pendingUpload` に残します。

#### nostr
- 種類 1 つにつき kind:30078 イベントを 1 つ使います。1 つのイベントが、その種類の備蓄リスト・目標・消費履歴を持ちます。
- `d` タグは `stock-burn-down/<ランダムな UUID>` です。d タグは暗号化されないので、種類名は入れません。
- content は次の JSON を NIP-04 で自分宛てに暗号化したものです。NIP-44 を持たない拡張機能（Nostore など）でも読めるように、常に NIP-04 を使います。以前の版が NIP-44 で保存したイベントは、NIP-44 を使える端末で開いたときに NIP-04 で書き直します。

```json
{
  "v": 1,
  "category": "缶詰",
  "updatedAt": 1794096000000,
  "stocks": [
    { "id": "8f0c…", "addedDate": "2026-11-08", "content": "シーチキン", "count": 3, "expiry": "2027-06-01" }
  ],
  "targets": [{ "id": "1b2e…", "addedDate": "2026-11-08", "count": 5 }],
  "history": [
    { "id": "c7d1…", "at": 1794096000000, "content": "サバ", "count": 1, "expiry": "2027-02-15" }
  ]
}
```

- 読み込み: kind:10002 の write リレー（なければ kind:3 のリレー、それもなければ既定のリレー）から、rx-nostr の backward strategy で `{"kinds":[30078],"authors":[<自分の公開鍵>]}` を取得します。受信したイベントは、全部そろうのを待たずに表示へ反映します。
- 保存: 変更から 1 秒後に、内容が変わった種類のイベントだけを publish します。種類が空になったときは、空のリストで上書きします。
- 同じ種類のイベントが複数あるとき（別の端末が別の d タグで作った場合など）は、品目を ID で合わせて表示します。目標はいちばん新しいイベントのものを使います。次にその種類を保存するときに、いちばん新しいイベントの d タグに書き、残りは空のリストで上書きして 1 つにまとめます。
